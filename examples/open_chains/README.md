# Three open modeling chains

These examples call pvlib, PyWake/TOPFARM and HOPP through autoengineering's
component runner. They compare explicit component replacements against an
immutable reference and save every completed, rejected and failed attempt.
See the [results](results/RESULTS.md) and [validation record](VALIDATION.md).

Run commands from the repository root. Pixi resolves macOS ARM and Linux x86-64
with separate solar, wind and hybrid environments. Model versions and dependencies
are pinned in pixi.toml and pixi.lock. Linux is locked but has not been executed
in this development session. No GPU, remote worker or paid solver is required.

```bash
pixi run -e solar python -m examples.open_chains.solar.run_workflow --fetch
pixi run -e hybrid python -m examples.open_chains.hybrid.run_workflow --fetch
pixi run -e solar python -m examples.open_chains.solar.run_workflow
pixi run -e wind python -m examples.open_chains.wind.run_workflow
pixi run -e hybrid python -m examples.open_chains.hybrid.run_workflow
```

Each script accepts `--smoke` and `--output PATH`. Output directories must be
empty. Default paths use a timestamp under that example's outputs directory.
Fetch verifies cached inputs and downloads only missing manifest entries. Changed
bytes fail validation. Solar downloads total about 384 MB; HOPP resources are
under 1 MB. Download once and rerun offline. Wind inputs ship with py-wake.
The development environment uses conda-forge timezonefinder 6.5.9 to avoid an
incompatible macOS wheel generated by a local PyPI source build.

Run tests after fetching inputs:

```bash
pixi run -e solar python -m pytest tests/test_open_chains.py -q
pixi run -e wind python -m pytest tests/test_open_chains.py -q
pixi run -e hybrid python -m pytest tests/test_open_chains.py -q
```

Optional dependency tests skip in other environments. The hybrid test executes
HOPP and CBC for five days; solar tests compare independent electrical solvers and
check transient causality; wind tests check upstream parity and feasible layouts.
The YAML graphs include identity adapters for secondary ports because the current
System graph stores one port pair on each directed edge. These adapters do not
add physical models or change numerical values.

| Example | Reference and changes | Decision and evidence |
| --- | --- | --- |
| [Solar](solar/README.md) | OEDI 9068, measured POA -> thermal model -> CEC DC model -> Sandia inverter. Faiman plus Prilliman reference; alternate module temperature models. | Minimize 2018 AC RMSE, then compare only baseline and frozen selection on 2019. |
| [Wind](wind/README.md) | Horns Rev 16-turbine subset -> TOPFARM layout -> fixed NOJ wakes -> annual energy. | Maximize modeled energy subject to fixed area and spacing, then check a finer direction grid. |
| [Hybrid](hybrid/README.md) | HOPP wind/PV generation -> coupled battery dispatch -> grid export -> scenario revenue. | Compare dispatch policies with fixed hardware/resources. Exclude policies failing the frozen physical screens. |

Artifacts include declared and selected system YAML, graph.mmd, trials.json,
selection.json, summary.json, report.md, input/software hashes and numeric NPZ
outputs. Solar saves the exact scored timestamps and observations. Wind records
inner wake evaluations and whether its optimizer converged. HOPP records final
SOC and throughput alongside revenue. Infeasible policies retain their arrays.
Failed execution produces a nonzero exit; infeasible candidates are an expected
comparison outcome when at least one feasible candidate remains.

These are finite component comparisons, not new Bayesian benchmark domains.
Their candidate lists stop at exhaustion. The existing five-domain target suite
has a separate 2000-call cap under examples/complex_models/PROTOCOL-2000.md.
Do not compare their different objectives as one accuracy metric.
