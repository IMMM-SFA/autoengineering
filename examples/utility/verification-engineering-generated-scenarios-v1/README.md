# New operating-scenario preparation

The new trusted preparer seals 24 operating-input scenarios before any suite
selection activity. Its policy fixes the task, bounds, uniform weights, sampler
algorithm and source-code hash. It requests one 32-byte seed and derives each
coordinate with a domain-separated HMAC-SHA256 computation and a fixed 52-bit
fraction. The seed and actual input rows remain private. No circuit outputs,
labels, convergence results or scores are generated.

A suite-level claim commits before entropy or source creation. Both output claims
also precede the draw. Changing output directories cannot obtain another draw for
the same task. Private completion commits before the public manifest. A private
reader requires the exact complete ordered selection barrier. It verifies the
original suite claim, source digest, seed commitment and deterministic derivation.
The public reader opens only metadata and does not derive private inputs.

Interruption controls cover failure before entropy, before private completion and
before public publication. An already committed private source can finish public
publication without randomness. A missing private completion remains uncertain
and cannot be regenerated. Changed policies, code, source bytes, units, seeds,
public metadata, scopes and barrier identities refuse. This is application-owned
trusted preparation, not an OS boundary or an admitted private scorer.

The actual control used an authored two-cell suite. Source generation completed
before its barrier. Early private access refused. After both cells were explicitly
sealed as `not_attempted`, the trusted reader verified all 24 input rows. The
suite's required one-start confirmation reserve remained unused. No scientific,
provider, host, fitting or scoring work was dispatched. The raw seed and input
rows remain only in `outputs/engineering-generated-scenarios-v2/private`. They are
not copied into this archive.

A fresh guarded reader verified the copied public commitments and authored suite
barrier with private reads, derivation, entropy, optional models, processes,
network, writes and clocks denied after module initialization. It did not recompute
the private draw or assert historical independence. The initial reader used the
wrong SuiteStore constructor keyword and refused without dispatch. The corrected
reader pins the loaded suite digest before replay. The related regression passed
56 tests, including 19 new scenario-source controls.

An initial authored prototype generated after selection. It was corrected before
the actual source draw to follow the plan's source-before-selection order. The
first control setup failed on a resource-cap field name before creating a suite
or drawing entropy. A launch then failed before output creation because namespace
imports lacked the checkout path. The corrected control initialized that path
explicitly and ran once. No failed output scope was overwritten.

This supplies a possible source-preparation path for newly generated operating
conditions under the existing coupled model. It does not establish an empirical
prediction claim or historical dataset independence. The existing 24-case grid
proposal and task dossier are unchanged and unevaluated. The successor proposal
is `examples/utility/proposals/engineering-generated-v1.json`.

Before a real study, the final preparation and execution grants must bind the
actual generated-source and public-manifest hashes before any selection work.
Protected coupled-model evaluation, physical checks, conventional recipe, useful
gains, budgets, repetitions and final task admission remain required. The existing
private scorer is not activated by this preparer. All four task dossiers remain
blocked drafts, the full comparison is unexecuted, and Part 5 is incomplete.
