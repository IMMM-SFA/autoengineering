# Frozen deterministic baseline confirmation reuse

An explicit utility-suite-v2 policy now names each baseline group, its designated
source, canonical model snapshot, default parameter digest, scorer identity and
exclusive cost shares. The policy wraps the comparison protocol digest and is
itself bound as the suite protocol digest. Changing it creates a new suite identity.
Legacy utility-suite-v1 serialization remains unchanged and rejects reuse fields.

The confirmation service verifies the common sealed model/selected-state artifact,
expected parameters and scorer before access. The journal refuses follower
reservations, including attempts to bypass the service. Only the designated source
can score. Repeated source dispatch replays its receipt. A score created before
publication requires explicit original-result recovery, retaining its charge.

Offline analysis automatically reconstructs declared follower references from a
successful feasible source receipt. Failed/infeasible sources remain recorded and
leave followers unscored. The report marks reused cells explicitly. Confirmation
cost records retain their physical quantity and source evidence while applying
the frozen logical shares. Unknown quantities remain unknown. No second scientific
runner, copied observation ledger or invented follower charge was introduced.

The initial regression recorded three failures and one pass for the missing
profile. A later checkpoint recorded 129 passes and one fixture failure caused by
an incorrect CSV filename in the test. That assertion now uses the existing
cost-allocations.csv export. The final focused contract/store/baseline/analysis/
report/scoring/recovery/CLI/cost suite passed 131 tests in 22.25 seconds. Ruff
passed. All earlier logs are retained. The complete utility regression passed
711 tests with 26 skips in 594.25 seconds. JUnit records 737 cases with no failures
or errors. All 12,475 pinned source/test/example/configuration files remained
unchanged. Its raw log, JUnit, command, environment, source pins and terminal
record are retained. This is not a full default or Bayes suite rerun.

A wheel built from isolated local sources matched all 201 core Python files. Six
separate installed CLI processes refused follower dispatch before and after source
scoring, interrupted source publication, refused retry, recovered the original,
and replayed it. Exactly one authored callback and one recovery occurred. There
was one access and source score, with no follower scoring reservation. This is an
explicit authored registration and public fixture, not private admission.

An isolated installed reader reconstructed relocated public evidence with original
fixture roots, sockets and child processes denied. It exported two logical scores
from one receipt and verified the export again. One physical confirmation
reservation was split into 0.25/0.75 logical shares, totaling one. Source/reused
markers were false/true. A saved v1 suite retained its canonical bytes/digest and
legacy allocation behavior. No scorer, model, provider or private label was used
by the reader. No container or remote job was launched in this increment.

The runtime and both worker payloads remain unchanged. The new profile covers
confirmation reuse after a common immutable reference has been sealed. Selection-
stage reference preparation still needs route integration. Determinism, protected
scoring and real task/data admission require separate qualification. Independent
custody, scientific thresholds, the final protocol, platform/host qualification
and independent results remain open. Part 5 remains incomplete.
