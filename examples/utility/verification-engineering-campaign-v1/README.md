# Engineering scientific controller verification

These records cover trusted supplied engineering tools on local macOS.
They do not establish route comparison, independent confirmation or utility.

- campaign-output.txt and campaign.xml retain focused controller tests.
- default-output.txt and default.xml retain all utility tests plus optimization recovery/run-spec tests.
- interoperability-output.txt and interoperability.xml retain engineering controller, process, domain and study checks with the coupled OpenMDAO runtime.
- documentation.xml retains documentation contracts.
- rehearsal-output.txt and rehearsal-source.json record the final exposed circuit tool rehearsal and captured-source comparison.
- offline-reader.json records reconstruction in the base environment with process, network and scientific registration imports blocked.
- summary.json records commands, outcomes and limits.

Original journals, jobs, stops, model sources and numerical observations remain
under ../development/engineering-campaign-v2. The earlier -v1 directory preserves
the earlier controller snapshot before case ownership was added. Do not relabel
its bytes as current or edit either record to relaunch its completed processes.

The earlier full default/Bayes suites and installed wheel predate this controller.
They were not rerun here. No frozen BO benchmark, provider, private confirmation,
remote host or Linux execution was used. Native-driver orchestration and suite
route brokers are not implemented by this controller.
