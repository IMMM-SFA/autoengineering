# Coupled-container source and cost contracts

The separate candidate callback connects the original generated-source binding to
a supplied container runtime interface. It verifies the frozen selection, active
access, registered runtime/code and exact inner-work/container reservations before
opening source cases. The runtime must pass preflight before that read. The packet
binds the grant, source binding, selected model, kernel and selected current.

`utility-load-cost-registration-v2` adds an immutable runtime registration. The
new `utility-container-load-work-v1` record pins the sanitized worker output and
the existing generic container execution receipt. Metadata reconstruction checks
the output envelope, all-case/partial-failure counts, score, runtime/image/code
identities and committed suite result. The earlier native callback and registration
format retain their original behavior and cost receipt IDs.

The callback writes an original completion pin before returning a score. Recovery
uses that pin without refreshing changed bytes, calling runtime preflight or
reopening source cases. Uncertain attempts keep their allocations and cannot retry.
If final publication fails, independently pinned public work can still account for
completed work, but it cannot authorize score recovery or another execution.

The focused suite passed 133 tests. It covers existing native reports and new
container metadata, invalid grants/registrations, tampering, source/read ordering,
partial failures, commit loss, recovery and CLI report/verify. Full lint passed.
No new physical model or container ran. These integration tests use a clearly
authored runtime double, including its resource observations and work counters.
They do not establish resource enforcement or physical work on those inputs.

The offline core-only wheel contains 226 Python modules and no example modules.
All package payloads match the selected current sources, and the installed payloads
match the wheel. A reader outside the checkout reproduced JSON/Markdown reports
and CLI verification with optional/model/example imports denied from startup.
After initialization it denied new imports, processes, network, clocks, writes and
outside file reads. The 48-file public archive excludes generated forcing rows,
private seed and private source payload. Global complete cost evidence remains
false. The first reader's obsolete assumption that physical unknown entries must
be nonempty failed after its earlier report checks passed. The original reader
and failure record remain beside the corrected reader.

The callback is not connected to a reusable live container owner yet. The saved
Linux fixed-worker control remains separate. Resource/owner-loss qualification,
real task admission and the independent utility study remain open. The v15
container register is unchanged. The frozen images and v6 wheel are unchanged,
but current core source now has a new module and a changed load-cost reader. Do
not call those frozen artifacts aligned with the entire current core tree.
