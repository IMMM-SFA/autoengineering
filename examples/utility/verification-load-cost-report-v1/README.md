# Common report integration for engineering work

The core metadata reader now joins pinned generated-load callback receipts into
common accounting and comparative report tables. It imports no example module,
source generator or optional scientific runtime. It does not launch a model.
The historical example reader and its native evidence remain unchanged.

`CostEvidenceSpec` binds the suite and every charged load callback's grant,
registration and optional work reference. Report-inputs v3 pins that cost-input
artifact and can also carry the existing effort input. Missing supplied proof
fails integrity checking. Null proof retains unknown work. Explicit inputs must
cover all charged load callbacks, so omitting an expensive callback cannot lower
the reported cost. Duplicate cells and changed journal heads are rejected.

The actual preceding native control contributes 24 completed model evaluations,
395 nonlinear iterations, 6,440 component calls and 1,975 component `_linearize`
calls. The latter includes Newton linearization and is not a FLOP count.
Counters, reservations and known-completed subsets have distinct resource names.
Do not sum those overlapping scopes. The common report still marks total cost
incomplete and preserves unknown generic process costs.

The [core-only wheel](build-install-result.json) contains 225 Python sources and
no example sources. Its copied-input build and isolated install used existing
setuptools and `--no-index --no-deps --no-compile`. Every package payload matched
its input pin and installed bytes. Dependencies were inherited from the local
macOS environment. This is not a Linux or full installed-workflow qualification.

The [current installed check](current-installed-result.json) reconstructs JSON,
Markdown and CLI verification outside the checkout. It denies example/framework
imports, new imports, writes, network, clocks and process creation after metadata
initialization. Repeated reports match exactly. The
[preceding installed wheel](legacy-installed-result.json) reconstructs the same
legacy report bytes under the same guard. Default report behavior remains exact.

The new core reader retains original metadata schemas so that grants, source
bindings, scorer identities and native work remain verifiable. It accepts no
executable callback supplied by report input. Comparative CSV export/reconstruction
is tested on an authored selected-state fixture. That fixture is not independent
scientific evidence. Source/scorer admission, protected execution, complete costs
and the four-family confirmation study remain open.

[Source transition](source-transition.json) records the three changed core files
and added metadata reader. The original 224-core/315-source v5 guest input package

the current source. No guest image, native evaluation or private source read ran
for this increment.

A [positive effort compatibility check](effort-v3-result.json) also compares

Its explicit fixture logs are authored values, not measured human work.
