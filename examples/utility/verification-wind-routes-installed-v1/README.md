# Installed relocated wind suite reader

A rebuilt local wheel installed in a temporary venv reconstructs a copied seven-cell
wind suite outside the checkout. The copy contains the sealed suite, execution plan
and exact archived sources. It excludes the original captured input directory.
Python runs with isolated startup. During reconstruction, guards deny the entire
original checkout, scientific imports through built-in and importlib entrypoints,
process dispatch and sockets.

The new explicit inspection mode preserves original path strings and physical job
identities without using them as new filesystem locations. It has no executor and
refuses request handling and cancellation. Live campaign opening retains its
original path checks. The reader verifies all seven selected states, original
callback and scenario receipts, parent/child evidence, source hashes and public
verify/status output. It does not rescore or execute a model.

`build.log`, `install.log`, `reader.log`, `offline-reader.json` and `partial-costs.json`
record the result. The venv inherits base dependencies. Pip installs only the local
wheel, without network or dependency resolution. This is not a minimal install or
installed scientific execution check. The reader implementation includes the later
inspection mode, while original scientific inputs retain the earlier runtime hashes.
Both versions are recorded in the source inventory.

The partial cost export retains unknown values. Independent weather, comparative
utility, full costs, Linux and another actual host remain unqualified. The temporary
venv and wheel are disposable. The saved original suite, reader source, wheel hash
and increment inventory preserve the evidence needed to repeat this check.
