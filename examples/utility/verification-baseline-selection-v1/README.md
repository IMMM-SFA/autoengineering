# Frozen baseline selection references

Baseline reuse policy v2 explicitly enables frozen_reference selection reuse.
The designated source runs the unchanged baseline once. Followers are new batch
v1.1 reference cases with zero host/scientific allowance. Batch v1.0 cases keep
their original rules and shape. Confirmation-only policy v1 does not implicitly
acquire selection reuse.

The policy is frozen into the suite identity and retains the original execution
plan digest. The source must precede followers in the frozen cell order. Supplied
model/default parameter checks happen before dispatch. Both prediction and
engineering coordinators use the same metadata-only follower path; the mixed
coordinator delegates to those paths. Source order, grants, scientific acceptance,
physical observations and the comparison matrix remain authoritative.

Each follower carries an immutable reference to the original committed child
result and the exact selected model/state artifacts. Readers verify that lineage
when finishing a parent result, reconstructing it and sealing selections. A source
cannot be another reference. Groups cannot overlap. A forged but internally
hash-consistent proof cannot finish, reconcile or supply a frozen selection.
Unknown source work never causes automatic replacement execution.

Recovery after reference evidence creation or child-case finish reuses the same
source and artifacts without new scientific starts. Source costs retain one
physical receipt and the frozen logical shares. Copy duration remains an explicit
unknown quantity. The profile does not claim that metadata operations are free or
that complete cost evidence is available.

The initial five tests failed for the missing policy/case path. The extended run
passed 41 tests with one test-fixture failure caused by assuming an evidence.json
filename; batch evidence uses receipt.json. That lookup now identifies the source
summary by content. The final baseline/contract/store/cost/report/confirmation
suite passed 82 tests in 66.25 seconds. A separate engineering fixture exercised
shared selection, sealing and one authored confirmation callback through the
versioned task scoring contract. All scores in that confirmation check are
authored fixtures, not independent observations. Raw logs are retained.

A 34-cell test crossed the 32-case child boundary with one scientific evaluation.
A confirmation-only policy still performed its original four selections. Direct
host/scientific reservations against reference cases were refused. Source-default
mismatch and reversed source order stopped before dispatch. Cost reconstruction
kept one process-start receipt, shared it across the logical cells and retained
three unknown copy-duration rows for the four-cell fixture.

A wheel built from isolated local sources matched all 202 core Python files.
An isolated installed CLI exercised run, resume and freeze, inheriting base
dependencies and directing child imports to that wheel extraction. Four logical
selections used one scientific process and one selected-state artifact. The saved
suite was relocated into this archive. Its installed offline reader verified all
four lineages and accounting with original fixture roots, sockets and process
starts denied. It neither imported an optional scientific framework nor executed
a model. Ruff passed after archiving, without an archive-specific exclusion here.

655.24 seconds. JUnit records 785 cases with no failures or errors. All
12,632 pinned source/test/example/configuration files remained unchanged.

retain their own source scopes. This remains the exposed scripted development
