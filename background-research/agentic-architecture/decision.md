# Part 1 architecture decision

Keep Autoengineering's evaluator and durable studies outside the agent host. Continue with a
small host-neutral control contract and CLI transport. This is a conditional direction for Part 2,
not an unconditional architecture selection: strict worker budgets, active cancellation, a second
host, and complete filesystem mediation remain unproven.

Both deterministic routes carry the same supplied candidate to the same recorded decision in
three runs each. One live Codex campaign also completed three serial role handoffs and a fresh
numerical decision. The plugin option is represented by a brokered CLI sketch, not an installed
plugin. No live standalone or second-host campaign completed before the token stop. This evidence
supports keeping the scientific contract independent of the host, but cannot establish which host
or scheduling approach offers lower total operating cost.

| Requirement | Result | Consequence |
| --- | --- | --- |
| Replayed candidate-to-decision path | Pass, both transports | Retain the shared contract sketch |
| Explicit development acceptance | Pass for routing fixture | No catchment-model adoption claim |
| Equal-budget child calibration and compatible recovery | Pass in fixture test and completed studies | Reuse existing controller semantics |
| Result-before-ack recovery | Pass with real evaluator | Keep logical/physical execution distinction |
| Changed identity and duplicate requests | Pass in contract tests | Carry into Part 2 |
| Protected comparison reads and record writes | Pass for macOS probes; same repository-denial profile used live | General file mediation and Linux remain untested |
| Strict resource enforcement | Fail: 56,128 observed tokens exceeded 50,000 | Do not recommend either route unconditionally |
| Active-child cancellation | Not tested; only cancellation before starting work | Implement execution supervision |
| Live host plugin and live standalone parity | Incomplete | CLI sketch is insufficient evidence of a finished plugin |
| Second-host portability | Not tested | Installed Claude remains a target only |
| General scientific validity | Not established | Qualify an explicit hydrology balance before broader work |

A dedicated harness has not been justified. The token overrun is a concrete gap in this host
integration, but the standalone option was not exercised live and alternatives were not exhausted.
A custom harness would add model invocation/accounting, context management, tool execution,
permission mediation, cancellation, transcripts, and provider upgrades. Effort was not measured,
so an estimate of calendar time would be speculation. Test an accounting adapter and one second
host before accepting that maintenance burden.

No reference code was adopted. The inspected repositories are MIT licensed, but future reuse still
needs retained notices and a dependency review. The prototype itself adds no package dependency,
public CLI command, or BO backend. Existing benchmark protocols and adverse evidence are unchanged.

## Part 2 handoff in dependency order

1. Freeze a campaign contract above numerical studies, with append-only events, explicit status,
   persistent failed-request accounting, and reservation/reconciliation semantics.
2. Qualify a scientifically meaningful task with explicit storage and flux accounting. Keep this
   Leaf River path as an orchestration fixture. Add unit/time/shape adapter semantics.
3. Define candidate snapshots and dependencies. Preserve immutable child study identity and bind
   the host runner separately from scientific evaluator identity.
4. Promote layered acceptance to a reusable evaluator contract. Include unavailable checks,
   model/infrastructure failures, and structured rejection without relaxing legacy behavior.
5. Supervise execution with active cancellation, bounded resources, and a tested filesystem and
   network boundary on each supported platform. Do not admit generated code before that check.
6. Save prompts before dispatch and record resolved model/provider identity. Add a subscription-aware host adapter that can reserve context/output tokens before a call.
   The observed 18,000-token input overhead must be understood before repeated live trials.
7. Package one host integration and test a second host using the same evaluator. Repeat matched
   live comparisons under a new explicit budget, since this investigation consumed 308 of 320
   allowed routing executions. Do not silently extend this task's budget.

Retain the numerical fixture, acceptance tests, child-controller integration, and tool request
shapes. Rewrite cumulative campaign snapshots as the specified journal. Replace the ad hoc live
runner with the supervised host adapter. Discard assumptions that a prompt, read-only sandbox,
or a worker's explanation alone establishes isolation or scientific validity.
